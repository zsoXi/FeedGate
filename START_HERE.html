FeedGate 3.0.0 / personal-use preview

No terminal.
No pairing.

A ready-made Chrome extension. The TypeSafe connection happens directly from the browser. Do not run the old START-FEEDGATE.cmd. You do not need Node, Python or a local server.

1Extract the whole package

Choose a permanent folder, for example D:\FeedGate-3.0.0. Do not run the extension directly from the ZIP. The folder must stay on disk after installation.

2Load the extension folder

In the Chrome address bar, type chrome://extensions. Enable Developer mode, click Load unpacked and select the extension subfolder. This is where manifest.json lives.

Chrome 120 or later is required. If an administrator blocks extension installation, do not work around that block.

3Key, consent, Connect & start

Open the FeedGate settings. In the Connect once and start browsing form, paste your direct TypeSafe API key. Tick the consent to send extracted post text to TypeSafe, leave All six supported feeds selected and click Connect & start. Accept the single Chrome prompt for the origins you keep selected; declining it leaves those sites off.

The extension makes one real request on a fictional post and then starts filtering. That test may be billed according to the provider's pricing.

Do not paste the key into a chat. A Vercel Gateway key and the old pairing code do not replace a TypeSafe key.

4Refresh the tab and scroll

After removing an older add-on, refresh the open tab. Start with Balanced mode. A small status pill shows detected items, pending analysis and filtering; click it to expand, and use minimize or close to hide it. Hiding the panel never pauses filtering and the popup can always reopen it.

Show restores a post temporarily. Keep this post stores an exception for that entry. Allow author adds the author to the local exception list. Alt + Shift + F reveals posts in the tab. The popup also offers Restore this site, Disable cosmetic filters and Reload this tab with filtering paused for a stuck page.

What about after a Chrome restart?

By default the key is available only in the browser session. To avoid retyping the key, tick Save an encrypted copy on this device and set your own passphrase, at least 12 characters. After a Chrome restart you unlock it with that passphrase in API & privacy.

There is no terminal and no new pairing code. The vault passphrase is not stored or recovered. Losing the passphrase means entering the key again.

When something does not work

Open Diagnostics → Export diagnostics. This produces a JSON file with counters, per-site states, cosmetic activity and safe error codes. It contains no key, post text, author names or raw cosmetic selectors. Review the file before sharing it, especially publicly.

Observe only mode records intended decisions without hiding. Jev errors do not create a hide decision; independent local rules can still act.

Scope of this release

X and Reddit are the primary adapters. LinkedIn, Facebook, Instagram and Wykop (beta) are secondary and stay off until you grant access. Text and available media descriptions are analysed, not images or videos. Wykop promotion notes are treated as ambiguous: nothing is auto-hidden by an old or unverified placement. This is a feed appearance filter, not a full network blocker.

139 Node tests, 59 Chromium DOM/UI scenarios, a 7-check unpacked-extension smoke test and 8 release integrity checks passed. API responses and browser interfaces were controlled in tests; the smoke test loaded the real extension folder in a local Chromium profile. No test used a real key, a signed-in feed or a live Wykop page.
