# Diagnostics schema

The export format is `feedgate-diagnostics`. Schema history: version 3 (2.1.0),
version 4 (2.1.1), version 5 (3.0.0), version 6 (3.1.0), version 7 (3.2.0), **version 8 (3.3.0)**.

The export is generated by the background worker and never contains keys, vault data,
passwords, post text, quoted text, author names, full browsing URLs, raw HTML, cosmetic
selectors, allowed-author names, or custom rule text. Cosmetic rules appear only as
random local references.

## Envelope

| Field | Meaning |
| --- | --- |
| `format` | Always `feedgate-diagnostics`. |
| `version` | `8`. |
| `extensionVersion` | Release version (`3.3.0`). |
| `rubric` / `policy` | `feed-v2.2.0` / `policy-3.3.0` (one optional topic question when a topic is active; 3.1.0's `author_muted` branch and 3.3.0's `topic_muted` branch). |
| `build` | Fingerprint: `{release, rubric, policy, detector, extraction, schema}` — e.g. `ad-3.0.0`, `extract-3.3.0`. A mismatch between source and shipped files fails the release check. |
| `generatedAt` | ISO timestamp. |
| `environment` | `chrome-extension`. |
| `privacy` | Plain-language statement of the exclusions, including that raw cosmetic selectors are never exported. |

## Section: `ui`

`{hudMode, feedsOpen, engineEnabled, preset, mode, grouping, thrift, thriftDelayMs}` — the persisted presentation
preference and engine switches. `hudMode` is `compact` | `expanded` | `hidden`. `grouping` and `thrift` are the
optional 3.3 toggles; `thriftDelayMs` is the visible-and-settled pause in milliseconds.

## Section: `sites`

Per-site state rows: `{site, label, status, selected, permitted, recoveryPaused,
effective, reason}`. `reason` is an enum and explains inactivity:
`engine_paused`, `not_selected`, `permission_required`, `recovery_pause`,
`refresh_required`, `ready`. A site that is *selected* but not *permitted* is never
reported as effective.

## Section: `cosmetic`

`{enabled, counts: {total, active, quarantined, disabled, deleted}, applications,
restorations, rejections, breakerActivations}`.

`cosmeticEvents` (last 100) records local hiding work separately from semantic
evaluations. Entries are enum-only:

```
{source:"cosmetic", kind:"applied"|"restored"|"rejected"|"breaker"|"undo"|"recovery_pause"|"recovery_resume",
 site:"x", ruleRef:"r-1a2b3c4d-…", reason:"self_write_rate", candidateAction:"collapse",
 appliedAction:"allow", at: 1789…}
```

`ruleRef` is a random per-rule identifier, not a selector. `candidateAction` and
`appliedAction` are `collapse` | `dim` | `allow` | `null`.

## Section: `renderer`

`{reportsReceived, lastHeartbeat, reportsLastHour, cleanupSites, note}` — page-report
presence and freshness. **An empty page list does not prove that no renderer is running**;
it means no content script published a report to the trusted side. `cleanupSites` lists
sites where effects may still exist until the tab reloads.

## Section: `provider`

`{requests, classified, cacheHits, cancellations, errors,
unaccounted: max(0, requests − classified − cancellations − errors), inputTokens,
outputTokens, lastLatencyMs, lastModel}`. `unaccounted` counts provider attempts with no
recorded outcome; it is a bounded accounting check, not an error by itself.

## Section: `logStats`

`{retained, capacity:150, dropped}`. Decision history is a rolling window; the counters
keep accumulating after the window fills. `dropped` makes the retention explicit.

## Section: `update`

`{running, onDisk, buildId, updateAvailable, checkedAt}` — the result of the last
on-disk build comparison made from the Updates panel; before any check has run the
values are `null` with a short `note`. `onDisk` is the release declared by the
packaged `build.json`; `updateAvailable` is `true` only when it parses as a different
semver release. The check reads a local extension file and makes no network request.

## Section: `decisions` (semantic log, newest retained 150)

Entries: `{at, site, action, wouldAction, source, rule, category, protected, conflict,
protectionEligible, sufficient, scores, model, ruleRef?, adEvidence, latencyMs, cached,
error}`.

- `source`: `policy`, `protection`, `allowlist`, `override`, `author`, `topic`, `local`, `unclassified`, `cosmetic`.
- `adEvidence` summary: `{status, markerKind, selectorId, ownerMatched, renderedLabel,
  evidenceKind, scope}` or `null`; `status` is `verified` | `ambiguous` | `none`.
- Counters (`metrics`) vs history: `metrics.decisions` is cumulative; `decisions.length`
  is the retained window; `cosmeticHidden`-style page counters are per-page observations.

## Privacy rules that hold by construction

- The decision log records reasons and scores, never the post body or the full URL.
- Cosmetic events record opaque rule references and enum reasons only.
- Selector text appears in exactly two places, both local: the rule manager UI and a
  settings export the user creates deliberately (`feedgate-settings.json`).
- The two real incident exports kept in `tests/fixtures/incident/` are used only by
  `tests/incident.test.mjs` for count replay.

## Compatibility

- Schema 6 (3.1.0) adds `settings.mutedAuthorCount` (a count only — muted author names never leave local storage) and the `author_muted` rule with the `author` source in decision entries. Nothing else in the envelope changed.
- Schema 7 (3.2.0) adds the `update` section (running build versus the packaged `build.json`); no new personal data is exported.
- Schema 8 (3.3.0) adds `ui.grouping`, `ui.thrift`, `ui.thriftDelayMs` and `settings.mutedTopicCount` (a count only — topic names never leave local storage), and decision entries may carry the `topic_muted` rule with the `topic` source. Nothing else in the envelope changed.
- Old schema-3 to schema-6 exports remain readable; they are plain JSON and the test
  suite replays them.
- Decision entries written by 2.1.0/2.1.1 do not carry the 3.0.0 `rule`/`adEvidence`
  fields where the old code had none; the replay tests treat missing fields as absent,
  not as zero.
