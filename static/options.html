Policy / version 3.0

Promotion is not a verdict.

Useful detail is a reason to be cautious about hiding, not proof that a claim is true. When in doubt, posts stay visible. Presets change explicit rules; no hidden author reputation is learned.

Inference controls

Changing thresholds reuses cached feature scores and reapplies the policy. Changing the model, rubric or personal question invalidates the corresponding cache key. Requests, including failed attempts, can be billed.

Direct HTTPS / no bridge

No cookies, passwords, screenshots or image/video files are requested. Known private routes and editors are excluded. These guards cannot recognise every sensitive post. Best-effort redaction does not guarantee anonymity. TypeSafe has its own processing and retention terms.

An unlocked key is not protected from malware, a compromised extension update or someone controlling your computer. Use a dedicated key and revoke it if compromised.

My cosmetic filters

—

Rules you create with the element picker. Raw selectors stay on this device and never appear in diagnostics. A rule is applied only while it passes the current safety checks; rejected rules are quarantined, not deleted.

Move your settings

Exports exclude keys and vaults but include your local cosmetic rules so you can move them. Imports require fresh site permissions and cloud consent. Exports use the 3.0 format; 2.1 and 2.0 exports are accepted, and unvalidated cosmetic rules migrate into quarantine.

Recovery

Restore persists a pause for one site first, then asks its open tabs to remove visible effects. Pending work is cancelled; other sites are untouched. If a page cannot respond, it stays paused and you can reload it paused.

Allowed authors

These local exceptions override semantic and labelled-ad post filtering, but not your cosmetic rules.

Muted authors

One click hides every post from an author on this site. This is a deterministic local list: no model request is used, “Keep this post” still wins for a specific post, and your cosmetic rules are unaffected. Muting and allowing are mutually exclusive for the same author.

Muted topics

Temporary or permanent topic mutes. Matching uses the same Jev request as filtering and can increase API usage. A passing mention or a quoted claim stays visible; “Keep this post” wins for a specific post; expired topics stop hiding posts automatically.

Saved post choices

“Keep this post” remembers a hash of the specific visible post, not a training label for the author. Edited content is evaluated again. Up to 2,000 choices stay on this device.

Same folder, same identity

Update without starting over.

FeedGate keeps a fixed extension identity, so your vault, settings and allowlists stay attached when you replace the files in the same folder and press Reload. Nothing downloads automatically: you decide when to update.

Loaded build

—

A check reads the packaged build.json from this folder and compares it with the running manifest. It makes no network request.

How to update in place

  1. Download the new release and unpack it.
  2. Copy the new extension/ files over the folder Chrome already loads. The same folder keeps the same extension identity.
  3. Open chrome://extensions, press Reload on FeedGate, then refresh your feed tabs.

Never press Remove: removing the extension deletes its local storage, including the encrypted vault. Open tabs show “Extension updated: reload this page” until you refresh them.

Key backup (move or restore)

If you move to a different folder or browser profile, export the encrypted vault here and import it after loading FeedGate. The file contains only the sealed vault: it is useless without your passphrase, and the plaintext key is never written to disk.

Upgrade note

Builds before 3.2.0 derived the extension identity from the folder path. The first 3.2.0 load uses the fixed identity, so an earlier vault does not carry over automatically: enter the API key once more, or import a backup that was exported under the same identity. After that, updates in place keep everything.
